# BioEngine

Микросервисная платформа для сбора, обработки и анализа биометрических данных и приема биодобавок.

## Смысл

Данные о здоровье и сне поступают от IoT-устройств, но часто хранятся в разных приложениях. Сервис принимает телеметрию, сохраняет её и в фоновом режиме сопоставляет с приемами витаминов (пример: «Как вечерний прием магния влияет на глубокий сон»), выдавая инсайты.

## Возможности

- **Архитектура (Kafka).** Телеметрия и аналитика разделены: Телеметрия пишет в Kafka, Аналитика читает из Kafka. Это позволяет масштабировать сервисы независимо друг от друга.
- **Защита от дублей.** Kafka гарантирует доставку At-least-once, поэтому одно событие может прийти дважды. Реализована защита через уникальный индекс в таблице — дубликаты не ломают бизнес-логику.
- **DLQ.** Если сообщение не удалось обработать 3 раза (например, ошибка парсинга или сбой БД), оно не блокирует очередь, а уходит в топик `telemetry.events.DLQ` для ручного разбора.
- **Virtual Threads.** Kafka-консьюмеры обрабатывают сообщения в виртуальных потоках, что позволяет обрабатывать тысячи событий без блокировки потоков ОС.
- **Graceful Shutdown.** Сервисы завершают текущие запросы перед остановкой, чтобы не терять данные при деплое.
- **Автоматическое создание топиков.** Топики создаются программно через `TopicBuilder` при старте Telemetry Service — не нужно вручную лезть в консоль Kafka.
- **Идемпотентный продюсер.** События отправляются в Kafka только после коммита транзакции в БД.
- **Flyway-миграции.** Схема БД управляется через SQL-скрипты. Для двух сервисов в одной БД используются разные таблицы истории миграций, чтобы избежать конфликтов.
- **API Gateway.** Единая точка входа маршрутизирует запросы на `telemetry-service` (8081) и `analytics-service` (8082).
